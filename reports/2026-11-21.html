1. 数据断供日，恰恰是检验你“选题系统”的时候

大部分做实体行业短视频的编导，选题逻辑是“追平台热榜”或“看AI日报有什么就写什么”。这种模式在数据正常的365天里看起来很勤奋，但它有个致命缺陷：你的内容供给完全依赖外部信息流。今天这种断供日一出现，选题就归零，团队只能临时拍脑袋。

真正稳的团队有一套“存量选题池”：把线下老板最常问的50个问题（例如“抖音拍了没人看怎么办”“客单价太低能不能提”“团购核销率怎么算”）列成清单，每条对应一版可复用的脚本骨架。AI日报的作用应该是往这个池子里加新钩子，而不是当天唯一的选题来源。

推演一下：如果今天你因为没新闻而发不出片，说明你的选题系统是单点依赖。如果今天你能从存量池里照样出片，说明AI只是你的加速器而非发动机——这才是实体老板愿意长期付钱编导的核心价值。建议今天就把这个池子建起来，用表格 + 标签梳理，按“老板痛点 / 平台机制 / 数据诊断”三类归档，每条注明适配的行业（餐饮/零售/教培/服务）。

顺带一个数据判断的经验：断供日不要拿“AI又进步了”当选题，这种泛泛的内容转化率极低，实体老板刷到只会划走。他们要看的是“我的店能不能用上”“要花多少钱”“多久见效”。所以宁可今天只发一条诊断类短视频，也不发一条AI趋势口播。

2. 给 viber 的提醒：外部接口失败时，你的原型要做到“优雅降级”

今天这次报错对做 vibe coding 原型的人来说，是一堂免费的产品课。你的原型里大概率也接了各种AI接口，一旦上游返回类似 error 567 这种非200状态、或者干脆超时，很多vibe出来的页面会直接白屏或者卡死在 loading 状态——用户的感受是“这东西坏了”，而不是“现在没数据”。

产品级的最低要求是三层降级：第一层重试机制（指数退避，最多2-3次）；第二层缓存兜底（展示上一次成功的数据，并注明“数据更新于X时间”）；第三层友好空态（明确告诉用户“当前数据源不可用，请稍后重试”，而不是转圈圈）。这三层加起来不到50行代码，但决定了原型是“demo”还是“能给人看的东西”。

更进一步，如果你打算把原型卖给实体老板当工具用，一定要在前端暴露数据新鲜度。老板不懂技术，但他懂“这个数字是不是今天的”。一个带着“更新于3小时前”标签的页面，可信度比一个永远显示“刚刚”的假实时页面高一倍。反过来，如果你用假数据自动填满，等真实数据来了和之前对不上，老板会当场失去信任。

实操建议：今天花半小时，把你手上任意一个原型接的接口，故意断网或改坏URL，看它表现如何。能把失败场景做体面的原型，才敢拿去做演示。这也是vibe coding最容易踩的坑——AI帮你把正常路径写得很漂亮，异常路径几乎全靠你自己想。

🛠️ Vibe Coding 可玩的

30分钟异常路径体检

挑你手上一个接了外部接口的原型，把接口URL故意写错，观察页面表现。目标：3 秒内给出明确的“数据不可用”提示，不白屏、不无限loading。这是原型从“能跑”到“敢演示”的分水岭。

三层降级最小实现

用一个封装的请求函数：重试（指数退避 x3）→ 读本地缓存的上一次结果 → 展示带时间戳的空态。约 50行代码，可以丢给 AI 帮你生成，但异常分支逻辑要自己盯。做好后你在演示时就能说“网络不好它也不会崩”，这句话对非技术客户的信任加成很大。

数据新鲜度徽标组件

做一个小组件：显示“更新于 X 分钟前”，超时后变灰并提示“数据可能不是最新”。用途：任何给实体老板看的看板/工具原型，加上它立刻显得专业。老板不看代码，但他认“这数字是不是新的”。

接口健康自检脚本

写一个每天定时跑的脚本，请求你依赖的关键接口，返回非200就发通知给自己。这样像今天这种 error 567 的情况，你在出片前就知道数据断了，而不是做到一半才发现。属于小投入高回报的稳定性补丁。
