1. 今日数据源拉取失败：这是编辑流程问题，不是内容问题

今天的日报遇到一个很典型的情况：热点抓取接口返回了 blocked（code 567），也就是说 aihot.virxact.com 这边的请求被拦截了，一条原始新闻都没拿到。按编辑原则，这种情况宁可空着，也不编造——因为对做实体短视频的人来说，一条假热点写进脚本，跑去门店拍，最后被老板和评论区拆穿，损失的是你的专业信任度，远大于今天少写一条。

但这种"数据断流"本身值得推演一下。从报错结构看，返回的是一个标准的 API 网关拒绝：有 error / code / requestId / help 链接 四个字段，requestId 说明请求确实到达了服务端并被记录，不是网络不通；help 直接指向 agent-api-recovery 页面，说明这是给自动化 agent 准备的"恢复指引"，也就是官方预期会有程序撞到这个错。常见的三类原因：一是频率限制，同一出口 IP 短时间请求太多；二是身份校验，缺少或过期的 API key / header；三是权限或套餐变更，账号侧被限流。

对读者的实际含义是：如果你的日报、选题库、脚本生成流程是自动化的，一定要设计"数据为空"的分支。很多人搭 agent 只考虑了"抓到了怎么处理"，没考虑"没抓到怎么办"，结果模型为了让输出看起来完整，开始胡编标题——这是 vibe coding 里最常见、也最危险的失控点。正确做法是：抓取层返回空时，直接走降级提示，明确告诉用户"今日无数据 + 原因 + 手动补录入口"，把不确定性暴露出来，而不是让模型脑补填补。

另外提醒一个操作细节：遇到 567 这类码，第一步不是重试刷屏，而是看 requestId——把它记下来，去 help 链接对号入座。盲目重试只会让限流更久，反而拖长恢复时间。这条经验同样适用于你给实体老板做的数据看板、团购核销监控这类小工具。

2. 把"日报"当产品做：一次断流暴露的选题系统脆弱性

顺着上面这条往下想，其实更值得聊的是：为什么这么多做短视频的人，一旦热点源断了就当天停摆？因为你把选题能力外包给了单一信息源。这不是技术问题，是产品结构问题。

一个健壮的选题系统应该是三层：第一层是热点层，也就是今天挂掉的这种 API，负责"今天大家在聊什么"；第二层是常态层，即你长期积累的实体行业母题——餐饮的复购、门店的到店转化、工厂的订单波动，这些不依赖任何 API，永远有货；第三层是素材层，你手里真实的门店视频、老板原声、评论区截图。热点层挂了，后两层照样能产出内容，只是时效性弱一点。

推演到执行层面：建议你今天就做一件小事——建一个30 条的"常青选题池"，纯手写，不联网。比如"为什么你的团购券核销率上不去""老板拍视频最常犯的 3 个表达错误"。这类选题的价值在于 不依赖时效，随取随用，还能反复改脚本重发。等热点源恢复，再把它当成增量补充。这样即使某天接口全挂，你的产出节奏也不会断。

给 vibe coding 的对应动作更具体：在你的抓取脚本里加一个 fallback 机制——主源失败时，自动从本地选题库随机抽 3 条填充，并在输出顶部打一个醒目的"降级模式"标记。十几行代码，但能让整个工具从"玩具"变成"敢每天用"的产品。判断也一样落到数据上：连续 3 天抓取失败，就该换源或加备用源，而不是继续等。

🎬 编导可用的

建一个 30 条常青选题池（今天就能做）

不联网、不依赖任何热点源。围绕实体老板的三个母题各写 10 条：客流、复购、口碑。每条写成"一句钩子 + 一个具体场景 + 一个反常识结论"，比如"团购券核销率低，不是价格问题，是核销时间设错了"。热点断供时直接从这里取货，拍摄不断档。

脚本模板做"降级版"备份

手里常备两套脚本结构：热点型（跟话题、要时效）和常青型（讲方法、可反复用）。热点型今天没素材就切常青型，别硬追。常青型脚本可以给同一位老板拍 3-5 条，素材复用率极高，适合排期紧张的档口。

把"数据不通"变成内容素材

如果你服务的老板本身就在做数字化尝试，今天这种"系统被限流"的真实小挫折，恰恰是好素材："我们给门店做的小工具，今天接口挂了，才发现没做兜底"。真实、有细节、不吹，比空讲 AI 概念更容易让同行老板有共鸣。

选题来源备份清单

除热点 API 外，至少备两条手动渠道：一是目标行业老板的真实微信群/评论区，二是你自己最近 7 天听到的老板抱怨。每周固定花 20 分钟抄 10 条原话进素材库，这是任何接口都替代不了的独家素材。

🛠️ Vibe Coding 可玩的

给抓取脚本加 fallback 分支

处理思路：请求返回非 2xx 或空数组时，不要抛错中断，而是读取本地 JSON 选题库随机抽 3 条，输出顶部标注"降级模式 · 数据源不可用"。关键是把 requestId 一并打印出来，方便事后排查。十几行代码，但让工具从"演示用"变成"每天敢用"。

写一个 requestId 记录器

把所有失败请求的 requestId、时间戳、错误码、接口名追加写入一个本地日志文件。连续失败 3 次就在页面顶部弹提示，而不是让程序静默重试。这套"失败可视化"的做法，对任何调外部接口的小工具都通用。

限流自保护：指数退避重试

如果是频率限制导致被拦，正确做法是首次失败等 30 秒、再失败等 1 分钟、再失败直接放弃并提示用户。别写 while 循环狂刷，那只会让限流窗口更久。这是调 API 的基本礼貌，也是小工具不背锅的关键。

把日报页面做成可离线打开的静态文件

今天这份 HTML 本身就是个好示范：单文件、内嵌样式、不依赖外链资源、断网也能打开。给老板交付时同理——别做必须联网才能看的东西，做成能发微信、能本地打开的单个 HTML，对方体验好，你在现场也好解释。
